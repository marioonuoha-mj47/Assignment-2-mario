## Overview
This site presents who I am, what I study, and the projects I have worked on. It has four pages (Home, About Me, Projects and Contact Me). Each page is rendered by its own Express route using EJS templates, and all pages share one header and footer through EJS partials.

## Features
- Four pages, each with its own Express route and EJS view
- Shared header (navigation bar) and footer (GitHub and LinkedIn links) built as EJS partials
- Projects page generated from an array of objects using an EJS loop
- Active-page highlighting in the navigation bar
- Responsive layout and components from Bootstrap 5
- Icons from Font Awesome
- Custom CSS layered on top of Bootstrap
- Deployed to the cloud on Render

## How It Works
1. `bin/www` starts the server and listens on the port from `process.env.PORT` (3000 locally).
2. `app.js` sets EJS as the view engine, serves the `public` folder as static files, and connects the router from `routes/index.js`.
3. Each route in `routes/index.js` uses `router.get(path, callback)` and calls `res.render(view, locals)` to produce a page.
4. Each view starts with `<%- include('partials/header') %>` and ends with `<%- include('partials/footer') %>`, so every page shares the same layout.
5. The Projects route sends an array of projects to the view, and `projects.ejs` loops through it with `forEach` to build one Bootstrap card per project.

| Route | View | Page title |
|---|---|---|
| `/` | `index.ejs` | Home |
| `/about` | `about.ejs` | About Me |
| `/projects` | `projects.ejs` | Projects |
| `/contact` | `contact.ejs` | Contact Me |

## Running Locally
**Requirements:** Node.js (LTS) and Git.

```bash
git clone https://github.com/marioonuoha-mj47/Assignment-2-mario
cd portfolio-site
npm install
npm start
```

Then open `http://localhost:3000` in your browser.

## Deployment
The site is deployed on **Render** as a Web Service connected to this GitHub repository.

- **Build command:** `npm install`
- **Start command:** `npm start`
- **Instance type:** Free
- Render redeploys automatically whenever changes are pushed to the `main` branch.

Note: on the free tier the first request after a period of inactivity can take up to a minute while the service wakes up.
